## Findings

### G2 (update) — Client generator: spec-derived identifier, type, literal, and path validation verified on `master`
- **Severity**: Medium (resolved)
- **Confidence**: Confirmed (all modified files read line by line; 177 new test cases in `SpecValidationTests` executed and passing)
- **Status**: Resolved since last audit (commit `477db7d`, PR #11)
- **Location**:
  - `dotnet-algorand-sdk/ClientGenerator/Extensions/SpecValidator.cs:1-174`
  - `dotnet-algorand-sdk/ClientGenerator/ABI/ARC56/ClientGeneratorARC56.cs:31-109,117-122,649`
  - `dotnet-algorand-sdk/ClientGenerator/ABI/ARC32/AppDescription.cs:37-40,79-140,142-203,358-365,500-502`
  - `dotnet-algorand-sdk/ClientGenerator/ABI/ARC32/StorageSection.cs:82-99`
  - `client-generator/Program.cs:32-151`
  - `README.md:177-180,226`
  - `test/SpecValidationTests.cs:1-519`
- **Description**: Commit `477db7d` enforces structural validation before code emission for both ARC56 and ARC32:
  1. **Identifiers & contract names** (`SpecValidator.RequireIdentifier`, `RequireContractName`, `RequireNamespace`): contract, method, argument (when non-empty), ARC32 state-variable, and event names must match `\A[A-Za-z_][A-Za-z0-9_]{0,199}\z` (anchored with `\z` rather than `$` so trailing `\n` is rejected). Contract names additionally reject Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM0-9`, `LPT0-9`). Namespaces and ARC32 `nameOverride` are validated at `ToProxy` / `ToSmartContractReference` entry and in `client-generator/Program.cs`.
  2. **ABI types & C# `TypeDetail`** (`SpecValidator.RequireAbiType`, `RequireCSharpType`): ABI types must match `\A(?:ref:)?(?:[A-Za-z0-9_(), ]|\[[0-9]*\]){1,10000}\z`, restricting bracket contents to digits only (closing array-length expression injection in `FixedLength`). ARC32 `TypeDetail` is checked with both a character whitelist and `SyntaxFactory.ParseTypeName` (full-span, zero-diagnostic, empty-rank-brackets only), plus `TypeHelpers.GetCSType` passes `sourceType` through `FormatStructName` (`ToPascalCase`, alphanumeric only).
  3. **Program strings, selectors & storage keys** (`RequireBase64`, `RequireLiteralSafeBytes`, `StorageSection.ToFieldName`): `source.*` (ARC32) and `byteCode.*` / `byte_code.*` (ARC56) must be valid base64; custom ARC32 method selectors must be printable ASCII excluding `"` and `\`; ARC32 state storage keys emitted as field names in `ToSmartContractReference` have all `[^\p{L}\p{N}_]` characters replaced with `_` (and leading digits prefixed with `_`).
  4. **Loader atomicity & ordering**: `ClientGeneratorARC56.LoadFromByteArray` clears `Contract = null` on entry and in `catch`, preventing a rejected spec from remaining loaded. `AppDescription.LoadFromByteArray` runs `ValidateSpecNames()` before sending any TEAL to `algodClient.TealCompileAsync`. Only `AppDescription.GenerateContractDescription` (from the developer's own Roslyn `SemanticModel`) sets `internal bool TrustedSource = true`.
  5. **CLI & error output hardening**: `SpecValidator.Show` escapes non-printable ASCII, `"`, and `\` to `\uXXXX` and truncates at 40 characters so error messages cannot inject terminal escape sequences or fake log lines. `client-generator/Program.cs` bounds `--url` downloads to 30 seconds and 20 MB and exits non-zero on invalid args, rejected specs, or I/O errors.
- **Recommendation**: Closed. Keep `SpecValidationTests` in the mandatory CI unit-test gate.

### G3 — Client generator: cyclic `Contract.Structs` in `IsFieldTypeDynamic` or deeply nested ABI tuples can cause `StackOverflowException` — new
- **Severity**: Low / Informational (process crash / availability only on a malformed spec; no code injection or key exposure)
- **Confidence**: Confirmed (traced directly in `ClientGeneratorARC56.cs` and `TypeHelpers.cs`)
- **Status**: New
- **Location**:
  - `dotnet-algorand-sdk/ClientGenerator/ABI/ARC56/ClientGeneratorARC56.cs:374-399` (`IsFieldTypeDynamic`) vs `:343-365` (`BuildTupleSignature`)
  - `dotnet-algorand-sdk/ClientGenerator/Extensions/SpecValidator.cs:54` (`AbiType` regex length 10,000) and `dotnet-algorand-sdk/ClientGenerator/ABI/ARC56/ClientGeneratorARC56.cs:292-337` (`ResolveOrCreateStruct`) / `dotnet-algorand-sdk/ClientGenerator/ABI/TypeHelpers.cs:145-210` (`TypeToStructs` / `ABITypeToCSType`)
- **Description**:
  1. In `ClientGeneratorARC56.cs`, `BuildTupleSignature(string structName, HashSet<string> visiting)` (`:343`) tracks `visiting` so a cyclic struct graph in `Contract.Structs` (e.g. `"structs": { "A": [{ "name": "x", "type": "A" }] }`) terminates safely during `ResolveAnonymousTuples()`. However, `IsFieldTypeDynamic(string abiType)` (`:374-399`, called during `defineStructs` and `defineEvents`) has no `visiting` set:
     ```csharp
     if (Contract.Structs.ContainsKey(trimmed))
     {
         return Contract.Structs[trimmed].Any(f => IsFieldTypeDynamic(f.Type));
     }
     ```
     A cyclic struct reference passes `ValidateSpecNames()` (`"A"` is a valid `AbiType`) and `ResolveAnonymousTuples()`, then recurses infinitely in `IsFieldTypeDynamic`.
  2. While `SpecValidator.RequireCSharpType` (`SpecValidator.cs:96`) catches deep-nesting stack errors on `TypeDetail` (tested at depth 1,500 in `SpecValidationTests.CSharpTypeValidatorRejectsPathologicalNestingWithSpecValidationException`), `SpecValidator.AbiType` (`:54`) allows up to 10,000 characters without a parenthesis-depth limit, so a ~4,000-deep nested tuple `(((...uint64...)))` passes `RequireAbiType` and recurses in `ResolveOrCreateStruct` / `ABITypeToCSType` without `RuntimeHelpers.EnsureSufficientExecutionStack()`.
- **Failure scenario**: A developer or service running `ClientGeneratorARC56` (or the CLI) against a malformed or hostile ARC56 spec containing a recursive struct definition or thousands of nested tuple parentheses hits an uncatchable `StackOverflowException` that terminates the host CLR process instead of throwing a catchable `SpecValidationException`. No code is emitted and no keys are exposed.
- **Recommendation**: Reject cyclic struct graphs in `ValidateSpecNames()` (and/or pass a `HashSet<string> visiting` to `IsFieldTypeDynamic` as `BuildTupleSignature` already does), and cap tuple/bracket nesting depth (e.g. <= 32) in `SpecValidator.RequireAbiType`.
